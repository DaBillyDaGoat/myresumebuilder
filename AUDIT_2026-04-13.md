## Findings

### P0 — Critical (Fixed)

---

**P0-1: `/api/save` blocked by RLS — all resume saves fail silently**  
**Status:** ✅ Fixed — commit `2e3ca20`

- **Root cause:** `app/api/save/route.ts` used the anon Supabase client (`NEXT_PUBLIC_SUPABASE_ANON_KEY`). RLS policy on the `resumes` table blocks anon INSERTs. The route uses fire-and-forget with `.catch(() => {})`, so every failure was swallowed. Zero rows in `resumes` table from real users.
- **Evidence:** `curl /api/save` → `{"error":"Database save failed","details":"new row violates row-level security policy for table \"resumes\""}`
- **Fix:** Changed import from `supabase` (anon) to `getSupabaseAdmin()` (service-role) in `app/api/save/route.ts`. Service-role client bypasses RLS. Verified: `curl /api/save` now returns `{"id":"ade4ef34-..."}`.

---

**P0-2: "Resume not found" on export screen — affects ALL users on ALL devices**  
**Status:** ✅ Fixed — commit `39bca81`

- **Root cause:** `PDFGenerator.tsx` calls `document.getElementById('resume-pdf-target')`. That element only exists inside `<ResumePreview>` (step 17). When the user clicks "Finalize My Resume →" the app moves to step 18, unmounting step 17. No `#resume-pdf-target` in DOM → error shown. This affected every browser, not just iOS.
- **Evidence:** All 4 sessions that reached `resume_generated` have 0 `export_pdf` events. Event data shows sessions stopping after `resume_generated`.
- **Fix:** Added hidden off-screen `<ResumeTemplate>` to step 18 JSX: `position: absolute; left: -9999px; aria-hidden="true"`. This keeps `#resume-pdf-target` in DOM at all times during export. Playwright test confirms: `#resume-pdf-target in DOM: true` on export screen, Download PDF click succeeds.

---

**P0-3: iOS bfcache wipes React state — export screen shows "Resume not found" after navigation**  
**Status:** ✅ Fixed — commit `39bca81`

- **Root cause:** On iOS, navigating away and back restores the page from bfcache. React in-memory state (`generatedResume`) is wiped, but the component re-mounts at step 0. No `#resume-pdf-target` exists, no resume data available.
- **Fix (3 layers):**
  1. Save `generatedResume`/`sectionOrder`/`contact`/`language` to `sessionStorage` immediately after AI generation.
  2. `useEffect` on mount: if state empty and sessionStorage has data, restore state and jump to step 18.
  3. `pageshow` listener: re-hydrate when `event.persisted === true` (bfcache restore signal).
  - Start Over clears sessionStorage. Spinner guard prevents step-0 flash during check.

---

**P0-4: Email broken for all users — Resend free tier domain restriction**  
**Status:** ⚠️ Partially mitigated — commit `fb76a7d`. **Root fix requires Billy action.**

- **Root cause:** `RESEND_FROM_EMAIL=onboarding@resend.dev`. Resend free tier only allows sending to the verified account owner email. All sends to real user emails return an error about domain verification.
- **Evidence:** `curl /api/email` with any address → `{"error":"Email restricted: Resend free tier..."}` even with owner email `billybuteau1@gmail.com`.
- **Mitigation shipped:** API now returns `{"error":"email_restricted"}` (422). `EmailForm` maps this to the "unconfigured" state, showing "Email service not set up yet — please download your resume using the button above instead." Instead of the raw technical error.
- **Root fix options (Billy must act):**
  1. **Connect a custom domain** to Resend account (recommended). Update `RESEND_FROM_EMAIL` to `noreply@yourdomain.com`.
  2. **Upgrade to Resend paid tier** (removes restriction).
  3. **Switch to SendGrid or Postmark** free tiers (broader allowances).

**P1-2: `resume_generated` event double-logged per session**  
**Status:** ⚠️ Minor data quality issue.

- `logEvent('resume_generated')` fires in `handleFinishQuestionnaire` in `page.tsx` (line 160, calls `/api/metrics`).
- `/api/save` also INSERTs a `resume_generated` event to `usage_metrics` after successful save.
- Result: 2 `resume_generated` rows per completed session.
- **Fix:** Remove the metrics insert from `/api/save` — `logEvent()` in `page.tsx` is sufficient. Or rename the `/api/save` event to `resume_saved` to distinguish them.

### P2 — Medium Priority

---

**P2-1: Spanish translations — 2 untranslated strings**

| Key | EN value | ES value |
|-----|----------|----------|
| `skills.interpersonal` | `Interpersonal` | `Interpersonal` (same — should be `Interpersonal` or `Trabajo en equipo`) |

The phone placeholder is acceptable (universal format). The `skills.interpersonal` label staying in English is a minor cosmetic issue in the ES flow.

---

**P2-2: Mobile layout — hidden resume template adds to `innerText`**

`position: absolute; left: -9999px` elements are excluded from visual rendering but included in `document.body.innerText`. This means screen scrapers and some accessibility tools would see resume content on the export screen. The `aria-hidden="true"` attribute correctly hides it from screen readers. No user-facing impact.

### P3 — Low Priority / Informational

---

**P3-1: `TOTAL_STEPS` constant is 15 but referenced in multiple places**  
The `wrapperProps.isLastStep: step === TOTAL_STEPS` correctly maps step 15 to the "Create My Resume" button. Step numbering is consistent.

**P3-2: In-memory rate limiter resets on Vercel cold start**  
`app/api/generate/route.ts` has an in-memory fallback rate limiter that resets when the serverless function cold-starts. This is fine since Upstash Redis is configured and working. The fallback is defense-in-depth only.

**P3-3: Annotation call uses the same rate-limited endpoint**  
After generating a resume (call 1), the app immediately fires an annotation call (call 2) to the same `/api/generate` endpoint from the same IP. This means heavy users consume 2 rate-limit tokens per session. At 10/hr this leaves room for 5 sessions per hour per IP. Acceptable for current scale.
